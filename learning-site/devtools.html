ブラウザ開発者ツール(DevTools) — HTMLとHTTPを「目で見る」

このページは診断ツール編(実作業編)です。 HTML・CSS・JavaScript・HTTP通信を、ブラウザに標準で入っている 開発者ツール(DevTools)でどう観察するかを、 「どのパネルが・ネットワークのどの層の・何を見る道具なのか」という視点で整理します。 コマンドライン版の診断は CLI診断ツールのページにあります。

Webページの表示がおかしい、通信が失敗する、動作が遅い——そんなとき、 まず開くべき道具がブラウザの開発者ツール(DevTools)です。 HTTPのやりとりや HTMLの構造、JavaScriptの動きを、 サーバに何も手を入れず、自分のブラウザの中だけで観察できます。 このページでは Chromium 系ブラウザ(Microsoft Edge / Google Chrome)の DevTools を題材に、 パネルごとに「何を目的に開き、何が分かるのか」を説明します。

DevToolsとは — 開き方と全体像

DevTools はブラウザに内蔵された、Web開発・調査のための道具箱です。次のいずれかで開きます。

  • F12 キー、または Ctrl+Shift+I(Mac は Cmd+Option+I)
  • ページを右クリック →「検証(Inspect)」

Edge も Chrome も、中身は同じ「Chromium」です。 Microsoft Edge と Google Chrome は同じ Chromium エンジンで動いているため、 DevTools の見た目・操作・機能はほぼ共通です。この解説はどちらでも通用します (Firefox や Safari にも同等の開発者ツールがありますが、実装は別系統です)。

DevTools は複数のパネル(タブ)に分かれていて、それぞれ見る対象の「層」が違います。 まず全体像を、下の一覧でつかんでください。

パネル 主な対象 何を見る道具か こんなときに開く(目的)
Elements(要素)表現層(DOM / CSS)描画後のHTML構造と適用CSS表示が崩れる・意図した見た目にならない
Console(コンソール)JavaScriptスクリプトのエラー・ログ・実行ページが動かない・JSエラーを読みたい
Network(ネットワーク)転送層(HTTP)全リクエスト/レスポンス・状態・時間通信が失敗する・遅い・APIの中身を見たい
Performance読み込み・描画処理のタイムラインページが重い・原因を特定したい
Application状態・保存(Cookie等)Cookie・ストレージ・キャッシュログイン状態・保存データを確認したい
Security暗号化(TLS/証明書)HTTPSの証明書・混在コンテンツ「保護されていない通信」の原因を見たい
Lighthouse総合品質性能・アクセシビリティ・SEOの監査ページ全体を採点し改善点が欲しい

公式ドキュメント。 各パネルの詳細な使い方は、Microsoft の公式解説が充実しています(日本語)。 → Microsoft Edge DevTools ドキュメント

Elements(要素)— 表現層:DOMとCSSを見る

対象レイヤ: 表現層(HTML/CSS)。 何を見る: ブラウザが実際に組み立てたDOM(描画後のHTML構造)と、 各要素に実際に効いているCSS、余白やサイズ(ボックスモデル)。

ここで見えるのは「サーバから届いた生のHTML」ではなく、JavaScriptによる変更も反映した今この瞬間の構造です。 要素にマウスを重ねると画面上の位置がハイライトされ、右側の Styles で「どのCSSが・どの順で適用され・どれが打ち消されたか」まで追えます。

目的: 「文字がはみ出す」「ボタンがずれる」といった見た目の崩れを、構造とスタイルの側から特定すること。 分かること・次の一手: 崩れの原因が「HTMLの入れ子」なのか「効きすぎ/効いていないCSS」なのかが切り分けられ、 その場で値を書き換えて直し方を試せます(変更はリロードで消える一時的なもの)。

Console(コンソール)— JavaScriptのエラーとログ

対象レイヤ: ブラウザ上で動く JavaScript。 何を見る: スクリプトのエラーメッセージ・警告・console.log の出力。その場で JavaScript を打ち込んで実行もできます。

目的: 「ページが途中で止まる」「ボタンが反応しない」ときに、裏で出ているエラーの正体を読むこと。 とくに Ajax(fetch)の失敗は、ここに赤いエラー(CORS違反、404、ネットワークエラー等)として現れます。 分かること・次の一手: エラーの種類とファイル/行番号が分かるので、原因が「自分のJSのバグ」なのか 「サーバ側の応答(→ Networkで確認)」なのかに進めます。

Network(ネットワーク)— 転送層:HTTPのやりとりを丸ごと見る

対象レイヤ: 転送層(HTTP)。 何を見る: ページを開いてから発生したすべてのHTTPリクエスト/レスポンスを一覧で。 1件を選べば、メソッド・URL・ステータスコード・ヘッダ・送受信ボディ・かかった時間まで、 HTTPのページで学んだ「生のメッセージ」がそのまま見られます。

これは 経路とエラーのページや CLIツールの curl -v を、GUIで見ているのと同じです。 一覧の各列の意味を押さえておくと、ひと目で当たりがつけられます。

列意味ここを見て分かること
Nameリクエスト先のファイル/URLどのリソースの通信かを識別する
StatusHTTPステータスコード200成功か、404/403/500系の失敗か。赤色は失敗
Typeリソースの種類(document / script / fetch / img など)HTMLかAPI呼び出しか画像か
Initiatorその通信を発生させた張本人どのスクリプト/要素がこのリクエストを出したか
Size転送サイズ重いリソース、キャッシュから来たか(「(memory cache)」等)
Time完了までの時間どのリクエストが遅いか
Waterfall時間軸上の内訳(待機/DNS/接続/TLS/ダウンロード)遅さが「待たされている」のか「転送中」なのか

知っておくと便利な設定が3つあります。

  • Disable cache: キャッシュを無効化して、毎回サーバから取り直す。古い状態に惑わされない。
  • Preserve log: ページ遷移やリダイレクトをまたいでも記録を消さない。ログイン後の飛び先などを追える。
  • スロットリング(Throttling): 回線速度を「低速3G」などに擬似的に落とし、遅い環境での見え方を再現する。

目的: 「どのリクエストが失敗しているか/遅いか」を特定すること。 分かること・次の一手: 失敗しているリクエストのステータスコードとヘッダが読めるので、 4xx(依頼側/ポリシー)か 5xx(サーバ側/経路)かの切り分けに直結します。 リクエスト自体が発生していないなら原因は JS側、というふうに調査範囲が絞れます。

キャッシュの罠に注意。 「直したはずなのに変わらない」の多くは、古いファイルがキャッシュから使われているせいです。 調査中は Disable cache をオンにしておくと、無用な混乱を避けられます。

Performance — 読み込みと描画の時間を分解する

対象レイヤ: ブラウザ内部の処理(読み込み・スクリプト実行・描画)。 何を見る: 記録ボタンを押してからの一連の処理を時間軸のタイムラインに分解したもの。 どこで時間を使ったか(スクリプト/レイアウト計算/描画)が色分けで見えます。

目的: 「ページが重い・カクつく」の原因を、感覚ではなく数字で特定すること。 分かること・次の一手: ボトルネックが「重いJavaScript」なのか「大きな画像の読み込み」なのか「頻繁な再描画」なのかが分かり、 手を入れる場所が決まります。まず全体を採点したいだけなら Lighthouse が手軽です。

Application(アプリケーション)— 状態と保存データを見る

対象レイヤ: ブラウザが保持する状態・保存領域。 何を見る: Cookie・LocalStorage・SessionStorage・Cache Storage・Service Worker など、 ブラウザに保存されているデータの中身。

HTTP はステートレス(サーバは前回を覚えない)なので、 ログイン状態などは Cookie 等に載せた識別子で表現されます。ここではその実物を確認・削除できます。

目的: 「ログインが維持されない」「古いデータが表示される」といった、状態にまつわる不具合を調べること。 分かること・次の一手: Cookie が正しくセットされているか、キャッシュに古い版が残っていないかが分かり、 「消してみたら直る/直らない」で原因の当たりがつけられます。

Security(セキュリティ)— 暗号化(TLS)と証明書を見る

対象レイヤ: 暗号化(TLS)。 何を見る: この接続がHTTPSで正しく保護されているか、使われている証明書は誰が発行した何者か、 そして混在コンテンツ(HTTPSページ内でHTTPのリソースを読んでいないか)。

目的: アドレスバーに「保護されていない通信」と出る、鍵マークが崩れる、といったHTTPSの警告の原因を特定すること。 分かること・次の一手: 「証明書の期限切れ/名前不一致」なのか「一部リソースがHTTPのまま」なのかが分かります。 証明書そのものをコマンドで詳しく見たいときは、CLIツールの openssl s_client に進みます。

Lighthouse — ページ全体を自動で採点する

対象レイヤ: ページ全体の総合品質。 何を見る: ボタン一つで、パフォーマンス・アクセシビリティ・SEO・推奨事項を自動診断し、点数と改善提案を出す監査ツール。

目的: どこから手を付けるべきか分からないときに、優先順位つきの改善リストを得ること。 分かること・次の一手: 「画像が最適化されていない」「文字色のコントラストが低い」など具体的な指摘が出るので、 詳しく掘るときに Performance や Elements へ進めます。

デバイスエミュレーションと回線再現。 DevTools 左上の端末アイコンでスマホ表示に切り替えたり、 User-Agent や画面サイズ、回線速度を擬似的に変えられます。 「PCでは正常だがスマホで崩れる」「遅い回線での見え方」を、実機がなくても再現して確認できます。

まとめ — パネルとサイトの地図の対応

DevTools のパネルは、本サイトが繰り返し使ってきた層の地図にそのまま重なります。 「今どの層を調べているのか」を意識すれば、どのパネルを開くべきか迷いません。

表現(何を)= HTML/CSS/JS

Elements / Console / Performance で構造・スクリプト・描画を見る。

転送(どう運ぶ)= HTTP

Network でリクエスト/レスポンス・ステータス・時間を見る。→ HTTP

状態・暗号化

Application(Cookie/保存)と Security(TLS/証明書)。
