HTML — リソースの表現とハイパーメディア

URIが「住所」、HTTPが「配送手順」だとすると、HTMLは運ばれてくる荷物の中身の書き方です。 このページでは、HTMLを単なる「ホームページの作り方」ではなく、 Webの技術体系における「リソースの表現」として学びます。 リンクを埋め込める、というHTMLの本質にも迫ります。 書籍『Webを支える技術』第4部「ハイパーメディアフォーマット」に対応する内容です。

HTMLは「リソースの表現」

HTTPのリクエストを送ると、レスポンスとして中身のデータが返ってきます。 その中身の代表格がHTML(HyperText Markup Language)です。 ここで、書籍『Webを支える技術』の重要な用語を2つ押さえましょう。

リソース

Web上の「情報そのもの」。たとえば「ユーザ123さんのプロフィール」という情報。URIで識別されます。

表現(リプレゼンテーション、representation)

そのリソースを「実際に書き表したデータ」。同じ情報でも、HTMLでもJSONでも書き表せます。

リソースと表現の関係は、「今日の東京の天気」という事実と、 それを伝える手段(テレビの天気図、新聞の文章、アプリの通知)の関係に似ています。 事実はひとつでも、伝え方は相手に合わせて何通りもあります。 Webでは「事実」がリソース、「伝え方」が表現です。

実際に、同じリソース /users/123 が、人間向けにはHTMLで、 プログラム向けにはJSONで返される実例を 全体像ページの比較で示しています。 URIもHTTPメソッドも同じで、違うのは表現だけ、という点を確認してみてください。

HTMLは「Webページを作る言語」である前に、リソースの表現フォーマットのひとつです。 この見方ができると、「HTMLとJSONは対立するものではなく、同じ役割(表現)の別形式」だと分かり、 後で学ぶAjaxやWeb API設計の話が一気につながります。

マークアップとは — 文章に意味のしるしを付ける

HTMLの「M」はマークアップ(markup)の頭文字です。 マークアップとは、文章に「ここは見出し」「ここは段落」という意味のしるしを付けること。 しるしにはタグという記号を使います。

タグの基本形 — 開始タグと終了タグで文章を挟む

<h1>私の自己紹介</h1>            ← h1 = 最上位の見出し
<p>はじめまして。山田です。</p>   ← p = 段落
<a href="https://example.com/blog/">ブログはこちら</a>
                                    ← a = リンク。href は「属性」

読み方のルールは3つだけです。

  1. 開始タグ <h1> と終了タグ </h1> で挟む 挟まれた範囲が「その意味を持つ部分」になる。終了タグには / が付く。
  2. タグ名が「意味」を表す h1 は heading(見出し)の1、p は paragraph(段落)、a は anchor(リンク)。
  3. 属性(attribute)で追加情報を渡す 開始タグの中の 名前="値" の部分。href 属性はリンク先のURIを指定する。

タグは「見た目の指定」ではなく「意味の指定」です。 <h1> を付けると太く大きく表示されますが、それはブラウザが 「見出しだからそれらしく表示しよう」と解釈した結果にすぎません。 見た目は次の次の節で登場するCSSの担当です。

HTML文書の基本構造

タグを組み合わせた、完全に動く最小のHTML文書を見てみましょう。 このままファイルに保存してブラウザで開けば表示できます。

最小の自己紹介ページ(profile.html)

<!DOCTYPE html>
<html lang="ja">
  <head>
    <meta charset="UTF-8">
    <title>山田太郎のページ</title>
  </head>
  <body>
    <h1>山田太郎の自己紹介</h1>
    <p>こんにちは。プログラミングを勉強中の山田です。</p>
    <ul>
      <li>趣味: 写真</li>
      <li>いま学んでいること: Webの仕組み</li>
    </ul>
    <p><a href="https://example.com/blog/">ブログはこちら</a></p>
  </body>
</html>

各部の役割は次のとおりです。

部分役割
<!DOCTYPE html> 「この文書はHTMLです」という宣言。おまじないではなく、ブラウザに最新のルールで解釈させるためのスイッチ。
<html lang="ja"> 文書全体の入れ物。lang="ja" は「日本語の文書」という意味で、音声読み上げや翻訳機能が参照する。
<head> 文書についての情報(メタデータ)を書く場所。画面には表示されない。
<meta charset="UTF-8"> 文字コード(文字をデータにする方式)の宣言。これがないと日本語が文字化けすることがある。現在はUTF-8一択。
<title> ページの題名。ブラウザのタブや検索結果、ブックマークに表示される。
<body> 画面に表示される本文すべてを入れる場所。

この <head> と <body> の関係は、HTTPメッセージの 「ヘッダ(メタデータ)とボディ(本体)」の関係とよく似ています。 「本体+それを説明するメタデータ」はWeb技術に繰り返し現れる構図です。

構造(HTML)・見た目(CSS)・振る舞い(JavaScript)の分離

Webページは3種類の言語の分業で作られています。

言語担当例
HTML 構造 — 何がどういう意味で書かれているか 「これは見出し」「これはリスト」「これはリンク」
CSS 見た目 — どんなデザインで表示するか 「見出しは青色」「行間を広く」「2段組みにする」
JavaScript 振る舞い — 操作にどう反応するか 「ボタンを押したらメニューを開く」「裏でデータを取ってくる」

先ほどの自己紹介ページに、CSSとJavaScriptを少しだけ足すとこうなります。 HTML本体(構造)は一切変えていないことに注目してください。

CSSを足す — head内に追加。見出しの色と行間だけ変える

<style>
  h1 { color: #0b6bcb; }
  p  { line-height: 1.8; }
</style>

JavaScriptを足す — body末尾に追加。ボタンに反応を付ける

<button id="greet">あいさつする</button>
<script>
  document.querySelector("#greet").addEventListener("click", function () {
    alert("こんにちは!");
  });
</script>

なぜ分けるのでしょうか。それは役割が違うものを混ぜると、あとで困るからです。 デザインだけ一新したいとき、CSSが分離されていればCSSファイルの差し替えで済みます。 また、構造が独立していれば、画面を持たないプログラム(検索エンジンなど)もHTMLの意味を読み取れます。 この「役割の分離」は、URI(識別)・HTTP(転送)・表現を分けたWeb全体の設計方針の縮図でもあります。

代表的なタグとセマンティックHTML

まず、本文でよく使う基本タグです。全部で100種類以上ありますが、最初はこれだけ知っていれば読めます。

意味タグ書き方の例
見出し h1〜h6 <h2>第2章</h2>(数字が小さいほど上位)
段落 p <p>本文の一段落。</p>
リスト ul / ol / li <ul><li>項目</li></ul>(ulは箇条書き、olは番号付き)
表 table / tr / th / td <tr><td>セル</td></tr>(trが行、tdがマス)
画像 img <img src="cat.png" alt="猫の写真">(altは画像の説明文)
リンク a <a href="/news/">ニュース</a>

セマンティックHTML — ページの構造にも意味を付ける

現在のHTMLには、ページ全体の区画に意味を与えるタグも用意されています。 これらを使った書き方をセマンティック(意味論的)HTMLと呼びます。

セマンティックタグでページの骨組みを作る

<body>
  <header>サイト名やロゴ</header>
  <nav>メニュー(ナビゲーション)</nav>
  <main>
    <article>この記事の本文</article>
  </main>
  <footer>著作権表示など</footer>
</body>

人間の目には、区画分けはデザイン(枠線や配置)で伝わります。 しかし機械には見た目が見えません。 検索エンジンは「main の中が本文だ」と判断して検索順位付けに使い、 スクリーンリーダー(画面を音声で読み上げるソフト)は「本文へジャンプ」「メニューへジャンプ」という操作を提供できます。 意味をタグで明示することは、機械と、機械の助けを借りる人への優しさなのです。

ハイパーメディアとしてのHTML — aタグとform

HTMLの「HT」はハイパーテキスト(HyperText)。 Webとはのページで見たとおり、 文書の中にリンクを埋め込めることがHTML最大の特徴であり、Webの本質です。 リンクの正体は「次にどのURIへ、どんなHTTPリクエストを送るか」の埋め込みです。代表が次の2つです。

aタグ — クリックでGETリクエストになる

HTML内のリンク

<a href="/news/2026/07/">7月のニュース</a>

クリックするとブラウザが送るHTTPリクエスト

GET /news/2026/07/ HTTP/1.1
Host: www.example.com
Accept: text/html

form — 入力内容がPOSTリクエストになる

フォームは、ユーザの入力を集めてサーバへ送る仕組みです。 method 属性がHTTPメソッドを、action 属性が送り先URIを指定します。

お問い合わせフォームのHTML

<form method="post" action="/contact">
  <label>お名前
    <input type="text" name="name">
  </label>
  <label>メッセージ
    <textarea name="message"></textarea>
  </label>
  <button type="submit">送信</button>
</form>

「佐藤花子」「こんにちは」と入力して送信ボタンを押すと、ブラウザはこんなHTTPリクエストを組み立てて送ります。

送信されるHTTPリクエスト(日本語は%表記に変換されて運ばれる)

POST /contact HTTP/1.1
Host: www.example.com
Content-Type: application/x-www-form-urlencoded
Content-Length: 95

name=%E4%BD%90%E8%97%A4%E8%8A%B1%E5%AD%90&message=%E3%81%93%E3%82%93%E3%81%AB%E3%81%A1%E3%81%AF

ボディの %E4%BD%90... は「佐藤花子」をパーセントエンコーディング (URIで使えない文字を%付きの16進数で表す方式 → URIのページ)した姿です。 name=値 のペアが & でつながれています。

aタグもformも、正体は「次に送るべきHTTPリクエストの設計図」をHTML内に埋め込んだものです。 ユーザはHTTPを知らなくても、リンクを押し、フォームを送るだけでWebを渡り歩けます。 「次に取れる行動をレスポンス自身が教えてくれる」——このハイパーメディアの性質は、 RESTで学ぶ重要な設計原則につながります。

HTML以外の表現フォーマット — XML・JSONと現在の姿

リソースの表現はHTMLだけではありません。 書籍第4部では、プログラム向けの表現としてXML(Extensible Markup Language)系の フォーマットが中心的に扱われていました。現在の主役はJSON(JavaScript Object Notation)です。 同じ「ユーザ123さん」というリソースを両方で書き比べてみましょう。

XMLでの表現 — タグで意味を示す(書籍時代の主役)

<user>
  <id>123</id>
  <name>佐藤花子</name>
  <joined>2024-04-01</joined>
</user>

JSONでの表現 — 名前と値のペアで示す(現在の主役)

{
  "id": 123,
  "name": "佐藤花子",
  "joined": "2024-04-01"
}

XMLはHTMLの親戚で厳密さが持ち味ですが、記述が冗長でした。 JSONは軽量で、JavaScriptからそのまま扱えるため、Web APIの表現として標準の座に就きました (→ Ajaxのページで実際に使います)。

HTMLに機械向けの意味を埋め込む — 過去と現在

書籍ではmicroformats(HTMLの属性にメタデータを埋め込む規約)やAtom(XMLベースの更新情報フォーマット)も 紹介されていました。これらは「人間向けのHTMLやXMLに、機械が読める意味を埋め込む試み」でした。 考え方はそのまま、現在は次の2つに受け継がれています。

OGP — SNSに投稿するとリンクカードが出る仕組み(head内のmetaタグ)

<meta property="og:title" content="Web学習サイトを公開しました">
<meta property="og:description" content="HTTP・URI・HTMLを体系的に学べます。">
<meta property="og:image" content="https://example.com/images/card.png">

JSON-LD — 検索エンジン向けの構造化データ(head内に埋め込むJSON)

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Web学習サイトを公開しました",
  "datePublished": "2026-07-01"
}
</script>

SNSでリンクを貼ると画像付きカードが表示されるのはOGPを、 検索結果にレシピの調理時間やイベント日程が出るのはJSON-LDを、それぞれのサービスが読んでいるからです。 「同じHTMLの中に、人間向けの表現と機械向けの表現が同居している」わけです。

現在のHTML標準 — Living Standardの時代

バージョン番号は廃止されました。 書籍刊行の2010年ごろは「HTML5」の登場前夜でしたが、現在のHTML仕様はWHATWGが管理する HTML Living Standardという「常時更新される1つの標準」になっています(2019年にW3Cから一本化)。 「HTML5」は現在では特定のバージョンではなく、この現代的なHTML一式を指す通称として残っています。

アクセシビリティへの注目。 セマンティックHTMLに加えて、WAI-ARIA(支援技術向けに役割や状態を属性で伝える仕様)の重要性が高まっています。 たとえば aria-current="page" は「ナビゲーションの中で現在いるページ」を読み上げソフトに伝えます。 誰にとっても使えることが、現在のHTMLの品質基準です。

Web Components。 独自のタグ(カスタム要素)を定義して部品として再利用する仕組みも標準化されています。 HTMLは「決められたタグを使う言語」から「部品を組み立てられる基盤」へと進化を続けています。
