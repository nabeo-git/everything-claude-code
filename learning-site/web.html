Webとインターネットは別物

インターネットは、世界中のネットワーク同士をつないだ「通信網そのもの」です。 その上では、メール、ファイル転送、ビデオ通話など、さまざまなサービスが動いています。 Web(World Wide Web)は、そのインターネットの上で動くサービスのひとつで、 「文書をリンクでつないで公開・閲覧する仕組み」として1990年ごろに生まれました。

インターネットが「道路網」だとすると、Webはその上を走る「宅配便サービス」のひとつです。 道路の上には宅配便以外にもバスやタクシー(メールや動画配信など)が走っています。 ただし現在では、この宅配便(Web/HTTP)があまりに便利なため、 他のサービスまでWebの仕組みに乗って運ばれるようになっています。

正体代表的な構成要素
インターネット 世界規模の通信網(インフラ) TCP/IP、DNS、ルータ、回線
Web その上で動く情報システム HTTP、URI、HTML(+ JSON、JavaScript など)

Webの本質① ハイパーメディア

Webの1つめの本質はハイパーメディアであることです。 ハイパーメディアとは、文書・画像・動画などの情報をリンク(ハイパーリンク)で相互につないだシステムのこと。 紙の本は先頭から順に読む「線形」の構造ですが、ハイパーメディアでは読者がリンクをたどって 自分の興味に沿って情報から情報へ飛び移れるのが特徴です。

HTMLで書くと、リンクはたったこれだけのコードです。この <a> タグこそがWebをWebたらしめています。

<p>
  詳しくは<a href="https://example.com/docs/http">HTTPの解説ページ</a>を
  参照してください。
</p>

リンク先はURIで指定します。つまりハイパーメディアが成立するには 「世界中のどの情報でも一意に指せる住所の仕組み」が不可欠です。 URIがWebの三本柱のひとつである理由がここにあります。→ URIのページ

Webの本質② 分散システム

Webの2つめの本質は分散システムであることです。 世界中の無数のサーバがそれぞれ情報を持ち、無数のクライアント(ブラウザやアプリ)がそこへアクセスします。 1台の巨大コンピュータではなく、膨大な数のコンピュータの連合体としてWebは動いています。

クライアント/サーバモデル

Webの通信は、必ず次の役割分担で行われます。

  1. クライアントがリクエストを送る ブラウザやアプリが「この情報をください」「このデータを保存してください」と依頼する。
  2. サーバがレスポンスを返す 依頼を処理して、結果(成功/失敗の別と、データ本体)を返す。

やりとりは常にクライアント側から始まるのがポイントです(サーバから勝手に話しかけることは基本的にありません)。 このシンプルな役割分担のおかげで、クライアントとサーバはお互いの中身(OSやプログラミング言語)を知らなくても連携できます。 Windowsのブラウザ、iPhoneのアプリ、Linuxのプログラムが同じサーバと会話できるのはこのためです。

世界規模の分散システムを成立させるための工夫(ステートレス性など)は HTTPのページとRESTのページで詳しく扱います。 「なぜWebはこんなに大きくなってもパンクしないのか」の答えがそこにあります。

Webの歴史をざっくりつかむ

年代出来事意味
1990年ごろ ティム・バーナーズ=リーがWebを発明 研究所(CERN)の文書共有のために、HTTP・URI・HTMLの3点セットを考案。
1993〜1995年 ブラウザ(Mosaic、Netscape)の登場と爆発的普及 画像が表示できるブラウザにより、Webが研究者以外にも広がる。
1990年代後半 ブラウザ戦争と標準化の混乱 各社が独自機能を乱発し「特定のブラウザ専用ページ」が乱立。標準化の重要性が痛感される。
2000年ごろ RESTの提唱 Roy FieldingがWebがうまくいっている理由を設計理論として整理(→ REST)。
2005年ごろ Ajaxの流行、Web 2.0 Google マップなどが登場し、Webページが「アプリケーション」になる(→ Ajax)。Web APIの公開も広がる。
2010年代 スマートフォンとクラウドの時代 アプリの裏側はほぼWeb API(HTTPS + JSON)に。『Webを支える技術』刊行(2010年)はこの入り口。
2015年〜現在 HTTPS標準化、HTTP/2(2015)・HTTP/3(2022)、SPAの普及 通信は原則暗号化に。プロトコルは高速化のため世代交代しつつ、HTTPの意味(メソッドやステータスコード)は変わらない。

歴史から学べる大事な教訓は2つあります。 ①独自仕様の乱立は必ず破綻し、標準への回帰が起きること。 ②HTTP/2やHTTP/3のような世代交代があっても、URI・メソッド・ステータスコードといった「意味の部分」は30年間ほぼ変わっていないこと。 だからこそ、本サイトで学ぶ基礎は今後も長く通用します。

Webを支える3つの技術と1つの思想

ここまでの話を、書籍『Webを支える技術』の核心である「三本柱+設計思想」の形で整理します。

URI — 識別

あらゆる情報に世界で一意な「住所」を付ける。ハイパーリンクの行き先を支える。

HTTP — 転送

住所(URI)を指定して情報を取り寄せ・書き込みするための共通の通信手順。

HTML — 表現

取り寄せた情報の「中身」の書き方。リンクを埋め込めるのでハイパーメディアが実現する。

REST — 設計思想

3つの技術を「どう組み合わせると良いシステムになるか」をまとめた考え方。

面白いのは順序です。HTTP・URI・HTMLが先に生まれて普及し、「なぜWebはこんなにうまくいったのか」を後から理論として説明したのがRESTです(2000年)。 RESTは発明された規格ではなく、成功したWebから抽出された設計原則なのです。

Webの3つの用途 — サイト・UI・API

書籍では、同じWeb技術が3つの異なる用途で使われていると整理しています。

用途説明例読み手
Webサイト 情報を公開・閲覧するもともとの用途 ニュースサイト、ブログ、企業サイト 人間(ブラウザ経由)
ユーザインターフェース(UI)としてのWeb 機器やソフトの操作画面をWebで提供する Wi-Fiルータの設定画面、社内システム、Webメール 人間(ブラウザ経由)
API(プログラム用インターフェース)としてのWeb プログラム同士がデータをやりとりする窓口 天気予報API、決済API、SNSの投稿API プログラム

3つとも、使っている技術は同じ「URI + HTTP + 表現(HTML/JSON)」です。 違いは全体像ページで見たとおり、返す中身と読み手だけ。 この「同じ仕組みの使い分け」という見方ができると、Webの技術記事がぐっと読みやすくなります。

現在は3つの境界が溶けつつあります。たとえばSPA(シングルページアプリケーション)では、 最初にWebサイトとしてHTMLとJavaScriptを受け取り、その後はJavaScriptがWeb APIを呼んで画面を更新します。 つまり1つのサービスの中で「サイトとしてのWeb」と「APIとしてのWeb」が同時に動いているのです。→ Ajaxのページ

誰がWebのルールを決めているのか

Webが世界中で相互接続できるのは、ルール(仕様)がオープンに標準化されているからです。主なプレイヤは次のとおりです。

団体担当成果物の例
IETF インターネットの基盤プロトコル HTTP(RFC 9110〜)、URI(RFC 3986)、TCP/IP、TLS。仕様書は「RFC」という文書番号で公開される。
WHATWG HTMLとブラウザ関連仕様 HTML Living Standard、URL Standard、Fetch Standard。常時更新型の「生きた標準」。
W3C Web関連技術の標準化(歴史的にHTMLも担当) CSS、WAI-ARIA(アクセシビリティ)など。HTML標準は2019年にWHATWGへ一本化された。

「RFC」はインターネット標準の仕様書のことで、本サイトでも「HTTPはRFC 9110で定義」などと参照します。 番号で管理されており、誰でも無料で読めます。仕様の原典に当たれるのもWebのオープンさの表れです。
